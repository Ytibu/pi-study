# 04.2 上下文

版本：Pi **v1.0.0**（`a13d35a74`） · 记录日期：2026-10-25

所属模块：[04 消息历史与上下文准备](04-消息历史与上下文准备.md)。上下文是本次请求实际提供给模型的信息；历史消息只是其中一部分。

## 1. 上下文包含什么

| 信息 | 作用 |
| --- | --- |
| 历史消息与当前输入 | 说明此前发生了什么、现在需要做什么 |
| 系统指令 | 规定行为规则，提供项目约定、工作目录等信息 |
| 工具声明 | 描述当前可调用的工具与参数 |
| 已回传的工具结果 | 提供文件内容、命令输出等实际执行结果 |

系统指令、工具声明和工具结果都可以通过消息承载。这里的分类用于理解信息来源，并不是把上下文划成互不重叠的数据结构。

项目在磁盘上的文件不会自动全部进入上下文。项目约定文件可由资源加载器读取；其他文件通常需要工具读取后回传。

## 2. 系统指令如何准备

[AgentSession._rebuildSystemPrompt()](../../pi/packages/coding-agent/src/core/agent-session.ts) 收集资源和当前工具信息，再由 [buildSystemPromptSections()](../../pi/packages/coding-agent/src/core/system-prompt.ts) 生成指令分区。

| 分区或来源 | 作用 |
| --- | --- |
| `preamble` | 基础角色说明，或配置提供的自定义提示词 |
| `tools`、`rules` | 工具用途摘要与使用规则 |
| `project_context` | 已加载的项目约定文件内容，如 `AGENTS.md` |
| `skills` | 满足条件时加入的技能说明 |
| `cwd` | 当前工作目录 |
| 附加提示词与自定义分区 | 补充配置或扩展提供的指令 |

默认资源加载器负责发现全局及工作目录祖先链上的约定文件，具体规则见 [resource-loader.ts](../../pi/packages/coding-agent/src/core/resource-loader.ts)。资源发现与信任控制的细节留待后续模块。

`_preparePromptAndToolLoadout()` 比较当前指令分区，只在有变化时生成 `system` 更新。`sections` 按名称替换分区，值为 `null` 时删除；它不是每次都追加一份完整提示词。

## 3. 从运行上下文到请求上下文

Pi 在不同层使用不同的数据类型：

| 类型或配置 | 内容与用途 |
| --- | --- |
| `AgentContext` | `messages` 保存运行消息，`tools` 保存宿主可执行的工具对象 |
| `AgentLoopConfig` | 保存所选模型、请求配置和转换函数等循环配置 |
| `TranscriptContext` | 提供商适配层使用的消息列表；系统指令和工具声明承载在 `system` 消息中 |

所选模型和认证用于发起请求，不属于聊天消息正文。`AgentContext.tools` 还包含执行能力，不能把整个运行快照直接当作模型请求发送。

[streamAssistantResponse()](../../pi/packages/agent/src/agent-loop.ts) 中的准备顺序是：

```text
运行消息（已有历史 + 当前输入 + system 更新）
  → transformContext()（配置了才调用）
  → convertToLlm()
  → normalizeContext({ messages: llmMessages })
  → streamFunction(model, llmContext, options)
```

| 步骤 | 作用 |
| --- | --- |
| `transformContext()` | 在请求边界变换消息；Pi 的扩展处理等可接入这里 |
| `convertToLlm()` | 将应用消息转换为模型兼容消息，如将压缩摘要转成用户消息、过滤被排除的 Bash 输出 |
| `normalizeContext()` | 统一请求上下文形式，得到 `TranscriptContext` |
| `streamFunction()` | 接入模型运行时，由对应适配器构造提供商协议请求 |

`normalizeContext()` 也支持将直接调用 API 时的 `systemPrompt`、`tools` 简写折入首条系统消息；在上述 Agent 路径中，这些信息已经位于消息中。它本身不负责摘要压缩，也不负责将所有系统更新合并成一条。

提供商是否支持对话中途的系统消息，会影响适配层如何保留或折叠这些更新；工具说明如何进入消息见下一篇。
