# 01 项目启动

版本：Pi **v1.0.0**（`a13d35a74`） · 记录日期：2026-10-24

本篇介绍如何在 Windows 上从 `pi/` 启动终端编码代理 CLI，以及它如何加载工作区源码。历史实测已覆盖 CLI、RPC 和 Bash；交互界面、登录和真实模型回复尚未验证。

## 1. 项目目录与启动目标

`docs/` 是学习文档站，`pi/` 是官方源码。两者独立安装依赖：查看本站只需运行文档站，学习 CLI 运行过程时再准备 Pi 环境。

以下源码路径均相对于 `pi/`：

| 路径 | 职责 |
| --- | --- |
| `pi-test.ps1`、`pi-test.bat` | Windows 源码启动入口 |
| `packages/coding-agent/` | CLI、交互模式、工具和会话管理 |
| `packages/agent/` | 代理循环、工具调用及状态管理 |
| `packages/ai/` | 模型目录、认证和服务 API 适配 |
| `packages/tui/` | 终端界面、键盘输入和原生平台能力 |

Pi 使用 npm workspaces。`pi/package.json` 没有 `dev` 或 `start` 脚本；源码 CLI 通过 `pi-test.ps1` 启动，无需先构建 `dist`。普通 CLI 启动也不需要数据库、Redis 或网页服务器。

## 2. Windows 源码启动

### 2.1 检查环境与版本

需要 Node.js ≥22.19.0、npm，以及可供工具命令使用的 Shell。优先使用已有环境。

从本项目根目录打开 PowerShell，执行：

```powershell
git submodule update --init pi
cd pi
git describe --tags --exact-match HEAD  # 预期 v1.0.0
node --version
npm --version
Get-Command node,npm,git,bash,pwsh -ErrorAction SilentlyContinue
```

下文命令均在 `pi/` 执行，另有说明的除外。运行前先阅读其中的 `AGENTS.md`。

### 2.2 安装依赖与补齐模型数据

```powershell
npm ci --ignore-scripts
npm run hydrate:model-data
npm run check:model-data
```

首次安装使用锁文件；`npm ci` 会重建依赖目录，其他进程正在使用依赖时不要重复执行。`--ignore-scripts` 遵循上游开发规则，禁用依赖生命周期脚本。

模型 JSON 位于 `packages/ai/src/providers/data/`，被 Git 忽略，克隆源码后需要单独补齐。校验成功时输出：

```text
Generated model data is valid.
```

补齐命令需要联网获取模型目录，不发送推理请求，也不改写生成的 TypeScript 目录文件。模型元数据来自执行时的服务目录，并非 v1.0.0 发布时的冻结快照；模型数量不应作为成功条件。

### 2.3 验证源码入口

```powershell
pwsh -NoProfile -File .\pi-test.ps1 --version
pwsh -NoProfile -File .\pi-test.ps1 --help --offline --no-approve --no-extensions
```

预期版本为 `1.0.0`，两条命令正常退出。帮助检查关闭自动联网、项目资源加载和扩展发现，以缩小验证范围。

也可直接执行 `.\pi-test.ps1 --version`，或使用 `pi-test.bat --version`。后者调用 Windows PowerShell 运行同一脚本，可用于排查直接执行 `.ps1` 时的策略限制；不必修改全局执行策略。

### 2.4 进入交互模式并认证

以下操作待在真实终端手动验证，输出不要重定向到文件或管道：

```powershell
pwsh -NoProfile -File .\pi-test.ps1
```

进入界面后，依次使用 `/login` 配置 API Key 或 OAuth、使用 `/model` 选择模型，再发送一个简单问题。支持的提供商见上游 [providers.md](../../pi/packages/coding-agent/docs/providers.md)。

需要检查 Bash 工具时，在编辑器输入：

```text
!printf 'Bash is working\n'
```

编辑器为空时按 `Ctrl+D` 退出；默认 `Ctrl+C` 第一次清空编辑器、第二次退出。可配置键位见 [keybindings.md](../../pi/packages/coding-agent/docs/keybindings.md)。

交互模式要求 stdin 和 stdout 都是真实终端；重定向任一流会选择 print 模式，因此捕获命令输出不能证明交互界面正常。

## 3. 配置与运行方式

### 3.1 配置位置

Pi 默认将用户配置放在 `~/.pi/agent/`；Windows PowerShell 中可用 `$HOME\.pi\agent` 定位。这些是运行时用户目录，不属于本仓库。

| 位置 | 内容 |
| --- | --- |
| 用户目录中的 `settings.json` | Shell 路径、默认模型、工具与界面设置 |
| 用户目录中的 `auth.json` | API Key、OAuth 等认证信息 |
| 用户目录中的 `models.json` | 自定义模型服务与模型覆盖 |
| 用户目录中的 `sessions/` | 持久化会话 |
| 工作项目中的 `.pi/` | 项目设置、扩展、技能与提示模板 |

`PI_CODING_AGENT_DIR` 可切换用户配置目录。历史 CLI/RPC 检查使用隔离配置，未修改默认用户认证。

项目 `.pi/` 资源受信任控制，首次交互启动可能显示提示。`--no-approve` 在当前进程忽略这些资源；`AGENTS.md` 等上下文文件的发现由 `--no-context-files` 单独控制。

### 3.2 在其他项目中运行

启动脚本的位置决定加载哪份 Pi 源码，当前工作目录决定 Pi 操作哪个项目。脚本不会自动切回源码目录。

例如从本仓库根目录进入文档项目，再调用源码入口：

```powershell
cd docs
& ..\pi\pi-test.ps1
```

历史实测曾从 `pi/packages/` 调用源码脚本，版本返回 `1.0.0`；保留调用者工作目录的行为也已由脚本源码确认。

### 3.3 一次性输出与 RPC

在 `pi/` 执行：

```powershell
# 需要认证；真实模型对话尚未验证
.\pi-test.ps1 --print "简要解释这个项目的用途"
.\pi-test.ps1 --mode json "简要解释这个项目的用途"

# 等待客户端通过 stdin 发送 JSONL 命令
.\pi-test.ps1 --mode rpc --no-session --model openai/gpt-4o-mini
```

JSONL 指每行一个 JSON 对象。RPC 可读取状态、执行工具和提交提示；历史检查只覆盖不调用模型的状态读取与 Bash 命令。示例模型 ID 不代表已验证其在线可用性。

`--no-session` 禁止持久化会话，仍可能创建配置文件。`--offline` 禁止自动网络活动，不提供凭据，也不会将远端模型变为本地模型。

### 3.4 其他入口

- **发布包**：上游支持 `npm install -g --ignore-scripts @earendil-works/pi-coding-agent@1.0.0`，安装后通过 `pi` 运行包内 `dist/bundle/cli.js`。该方式未实测，且不运行本仓库源码。
- **Linux/macOS**：源码入口为 `./pi-test.sh`，未实测。v1.0.0 的该脚本先加载 `src/experimental/cli.ts`，Windows 脚本加载 `src/cli.ts`，两者入口存在差异。

## 4. 启动链路与源码入口

Windows 的基础调用路径（相对于 `pi/`）：

```text
pi-test.ps1
  → node --import <source-resolver.ts 的 file URL> src/cli.ts
  → source-resolver.ts 按根 tsconfig.json 的 paths 解析工作区源码
  → cli.ts 调用 setupCli() 和 main(args)
  → main.ts 加载参数、配置、会话、模型和工具
  → InteractiveMode / runPrintMode / runRpcMode
```

Node.js 可处理可擦除的 TypeScript 语法，但不会自动应用 `paths` 别名。源码解析器将 `@earendil-works/*` 映射到工作区 `src`，因此无需预先生成全部 `dist`。

| 源码入口 | 阅读目的 |
| --- | --- |
| [package.json](../../pi/package.json) | workspaces、环境要求与根命令 |
| [pi-test.ps1](../../pi/pi-test.ps1)、[pi-test.bat](../../pi/pi-test.bat)、[pi-test.sh](../../pi/pi-test.sh) | 平台包装、参数转发与入口差异 |
| [source-resolver.ts](../../pi/packages/coding-agent/src/experimental/source-resolver.ts)、[tsconfig.json](../../pi/tsconfig.json) | 工作区源码别名解析 |
| [cli.ts](../../pi/packages/coding-agent/src/cli.ts)、[setup.ts](../../pi/packages/coding-agent/src/cli/setup.ts)、[main.ts](../../pi/packages/coding-agent/src/main.ts) | CLI 初始化、参数分流与运行时创建 |
| [config.ts](../../pi/packages/coding-agent/src/config.ts) | 版本、资源与用户配置目录 |
| [shell.ts](../../pi/packages/coding-agent/src/utils/shell.ts) | Bash 与 PowerShell 查找规则 |
| [ai/package.json](../../pi/packages/ai/package.json)、[check-model-data.ts](../../pi/packages/ai/scripts/check-model-data.ts) | 模型数据补齐与校验 |

`--version` 在参数解析后提前退出，`--help` 还会初始化部分运行时以收集扩展参数。入口成功、会话成功和真实模型回复是不同层级的验证。

## 5. 启动问题与处理

以下为 2026-10-24 的历史排障记录，保留当时的现象与结论，供复现时参考。

| 问题 | 原因与处理 | 历史结果 |
| --- | --- | --- |
| P01：安装报 `ENOTCACHED`、`only-if-cached` | 执行环境限制联网，缺失依赖未命中缓存；允许联网后重试原命令。普通终端可先检查 `npm config get offline` | 安装成功，未改 registry、锁文件或依赖版本；首次伴随的目录清理 `EPERM` 也未阻断重试 |
| P02：npm 配置与依赖警告 | npm 11.6.2 不识别上游的 `min-release-age=2`；`autoevals@0.3.0` 声明 pnpm 要求；另有 `prebuild-install`、`node-domexception` 弃用警告 | 保留上游配置与依赖，CLI/RPC 检查通过；不能认为版本保护已生效，评估功能未验证 |
| P03：模型 JSON 缺失 | 数据目录被 Git 忽略，需执行 `hydrate:model-data` 和 `check:model-data` | 启动前补齐并校验通过；未实际触发缺失数据的启动异常，生成的 TypeScript 和锁文件无改动 |
| P04：直接运行 `cli.ts` 找不到 `dist/index.js` | `node packages/coding-agent/src/cli.ts --version` 绕过源码解析器，按包发布入口查找未构建的文件 | 复现 `ERR_MODULE_NOT_FOUND`，改用 `pi-test.ps1` 或 `.bat` 后返回 `1.0.0` |
| P05：自动选择 WSL Bash | Git 安装在非默认盘符，常见目录检查未找到 Git Bash，转而选中 PATH 中的 WSL Bash | 默认 WSL `printf` 成功；隔离配置显式指定 Git Bash 后，RPC Bash 也成功 |
| P06：子进程报 `EPERM` / `E_ACCESSDENIED` | 自动化环境限制创建进程，另出现 Git Bash signal pipe 错误 | 在允许本地子进程的环境重跑后通过，不能直接归因于 Pi 缺陷 |
| P07：有模型目录仍无法对话 | 元数据不等于凭据；应通过 `/login` 认证后再 `/model` 选择模型 | 无凭据时 `--list-models` 返回 `No models available`；`--print hello` 与 `auth check` 均失败，未调用模型 |
| P08：交互测试缺少 tmux | Windows PATH、Git Bash 和 WSL 中均未找到 tmux | 未安装额外工具，交互界面待验证；自动化测试需遵循上游 [交互测试说明](../../pi/.pi/skills/interactive-testing.md) |

遇到模型数据 stale/missing 时，重新补齐并校验，不手写 JSON 或编辑 `models.generated.ts`。如需指定 Git Bash，将实际安装位置的 `bin/bash.exe` 路径合并到 `settings.json` 的 `shellPath`，保留其他设置。

认证检查可使用 `auth check --provider openai --json --no-refresh`。历史无凭据检查返回 `not_ready / credentials_not_configured`，退出码 `1`。不要将密钥打印输出写入文档；`--no-env` 只清理部分环境变量，也不会清空 `auth.json`，隔离验证还需单独配置目录与子进程环境。

## 6. 历史验证范围

实测环境：Windows x64、Node.js `24.12.0`、npm `11.6.2`、Git `2.55.0.windows.5`；源码直接检出 v1.0.0 标签（detached HEAD）。安装时使用本机已有的 npmmirror registry，此镜像并非项目要求。

| 检查 | 结果 |
| --- | --- |
| 依赖安装、模型数据补齐与校验 | 联网重试后成功 |
| `.ps1` / `.bat` 的 `--version`、受限加载的 `--help` | 版本 `1.0.0`，退出码均为 `0` |
| 从其他工作目录调用、绕过解析器的失败复现 | 符合脚本与模块解析行为 |
| 默认 WSL Bash、显式 Git Bash 的 RPC 命令 | 输出 `Bash is working`，退出码 `0` |
| 隔离配置、离线 RPC `get_state` 与关闭 stdin | `success: true`，初始消息数 `0`；子进程正常退出 |
| 交互界面、键盘、主题、登录、真实模型回复及模型自动调用工具 | 未验证 |
| Pi 全量构建与测试、全局安装、Linux/macOS、实验 server/client | 未执行或未验证 |

历史原始日志保存在当时源码工作区被忽略的 `.artifacts/startup-study/`，不随本仓库分发。以上结果来自该次启动记录；本篇整理和文档站构建不代表重新执行了 Pi 运行验证。
