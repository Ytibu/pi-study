# 01 项目启动

版本：Pi **v1.0.0**（`a13d35a74`） · 记录日期：2026-10-24 · 修订日期：2026-10-25

本篇介绍 Windows 源码启动：准备依赖和模型数据，通过 `pi-test.ps1` 运行 CLI。历史实测覆盖版本、帮助、RPC 状态读取和 Bash 命令；交互界面与真实模型回复尚未验证。

## 1. 项目结构

`docs/` 是文档站，`pi/` 是官方源码，两者独立安装依赖。以下路径相对于 `pi/`：

| 路径 | 作用 |
| --- | --- |
| `pi-test.ps1`、`pi-test.bat` | Windows 源码启动入口 |
| `packages/coding-agent/` | CLI、工具和会话管理 |
| `packages/agent/` | 代理循环与工具调用 |
| `packages/ai/` | 模型目录、认证和 API 适配 |
| `packages/tui/` | 终端界面与键盘输入 |

Pi 使用 npm workspaces，根 `package.json` 没有 `dev` 或 `start` 脚本。源码 CLI 无需先构建 `dist`，也不依赖数据库或网页服务器。

## 2. Windows 启动步骤

### 2.1 检查环境

需要 Node.js ≥22.19.0、npm 和工具命令使用的 Shell。从本项目根目录打开 PowerShell：

```powershell
git submodule update --init pi
cd pi
git describe --tags --exact-match HEAD  # 预期 v1.0.0
node --version
npm --version
Get-Command node,npm,git,bash,pwsh -ErrorAction SilentlyContinue
```

下文命令默认在 `pi/` 执行，运行前先阅读其中的 `AGENTS.md`。

### 2.2 安装依赖与补齐模型数据

```powershell
npm ci --ignore-scripts
npm run hydrate:model-data
npm run check:model-data
```

- `npm ci --ignore-scripts`：按锁文件重建依赖，禁用生命周期脚本；依赖正被其他进程使用时不要重复执行。
- `hydrate:model-data`：联网补齐被 Git 忽略的 `packages/ai/src/providers/data/` JSON，不发送推理请求或改写生成的 TypeScript 文件。
- `check:model-data`：检查数据完整性，成功输出 `Generated model data is valid.`。

模型元数据取自执行时的服务目录，并非 v1.0.0 冻结快照，模型数量不作为成功条件。

### 2.3 检查版本和帮助

```powershell
pwsh -NoProfile -File .\pi-test.ps1 --version
pwsh -NoProfile -File .\pi-test.ps1 --help --offline --no-approve --no-extensions
```

预期版本为 `1.0.0`，两条命令均正常退出。帮助检查关闭自动联网、项目资源加载和扩展发现。

也可直接执行 `.\pi-test.ps1 --version`，或使用调用同一脚本的 `pi-test.bat --version`，无需依次运行两种入口。

### 2.4 交互与认证（待手动验证）

在真实终端运行，不要重定向输入或输出：

```powershell
pwsh -NoProfile -File .\pi-test.ps1
```

进入界面后，用 `/login` 配置认证、`/model` 选择模型，再发送问题。支持的提供商见 [providers.md](../../pi/packages/coding-agent/docs/providers.md)。检查 Bash 工具可输入 `!printf 'Bash is working\n'`。

编辑器为空时按 `Ctrl+D` 退出；默认 `Ctrl+C` 第一次清空、第二次退出。stdin 或 stdout 被重定向时会选择 print 模式，不能用于验证交互界面。

## 3. 配置与运行方式

### 3.1 配置位置

默认用户目录为 `~/.pi/agent/`，Windows 可用 `$HOME\.pi\agent` 定位；`PI_CODING_AGENT_DIR` 可切换该目录。

| 位置 | 作用 |
| --- | --- |
| 用户目录 `settings.json` | Shell、默认模型、工具与界面设置 |
| 用户目录 `auth.json` | API Key、OAuth 认证 |
| 用户目录 `models.json` | 自定义模型服务与模型覆盖 |
| 用户目录 `sessions/` | 持久化会话 |
| 工作项目 `.pi/` | 项目设置、扩展、技能与提示模板 |

项目资源受信任控制。`--no-approve` 在当前进程忽略这些资源，`AGENTS.md` 等上下文文件由 `--no-context-files` 单独控制。历史 CLI/RPC 检查使用隔离配置，未修改默认用户认证。

### 3.2 在其他项目中运行

脚本位置决定加载哪份源码，当前工作目录决定 Pi 操作哪个项目。例如从本仓库根目录执行：

```powershell
cd docs
& ..\pi\pi-test.ps1
```

### 3.3 一次性输出与 RPC

在 `pi/` 执行：

```powershell
# 需要认证，真实模型回复未验证
.\pi-test.ps1 --print "简要解释这个项目的用途"
.\pi-test.ps1 --mode json "简要解释这个项目的用途"

# 通过 stdin 接收 JSONL（每行一个 JSON 对象）命令
.\pi-test.ps1 --mode rpc --no-session --model openai/gpt-4o-mini
```

RPC 支持状态读取、工具执行和提示提交；历史检查只覆盖前两项。示例模型的在线可用性未验证。

`--no-session` 禁止持久化会话，仍可能创建配置文件；`--offline` 禁止自动网络活动，不会让远端模型离线运行。

### 3.4 其他入口（未实测）

- **发布包**：`npm install -g --ignore-scripts @earendil-works/pi-coding-agent@1.0.0`，安装后用 `pi` 运行包内 `dist/bundle/cli.js`。
- **Linux/macOS 源码**：使用 `./pi-test.sh`。平台入口差异见 [02 pi-test 启动脚本](02-pi-test启动脚本.md)。

## 4. 启动链路与源码入口

```text
pi-test.ps1
  → Node.js 预加载 source-resolver.ts，运行 src/cli.ts
  → setupCli() → main(args)
  → 加载参数、配置、会话、模型和工具
  → InteractiveMode / runPrintMode / runRpcMode
```

源码解析器按 `tsconfig.json` 的 `paths` 将工作区包映射到 `src`，因此无需先构建全部 `dist`。具体机制见第 02 篇。

| 源码 | 作用 |
| --- | --- |
| [package.json](../../pi/package.json) | workspaces、环境要求与根命令 |
| [cli.ts](../../pi/packages/coding-agent/src/cli.ts)、[setup.ts](../../pi/packages/coding-agent/src/cli/setup.ts)、[main.ts](../../pi/packages/coding-agent/src/main.ts) | CLI 初始化与运行模式分流 |
| [config.ts](../../pi/packages/coding-agent/src/config.ts) | 版本、资源与用户配置目录 |
| [shell.ts](../../pi/packages/coding-agent/src/utils/shell.ts) | Bash 与 PowerShell 查找规则 |
| [ai/package.json](../../pi/packages/ai/package.json)、[check-model-data.ts](../../pi/packages/ai/scripts/check-model-data.ts) | 模型数据补齐与校验 |

`--version` 在参数解析后提前退出，`--help` 还会初始化部分运行时；两者成功不代表模型调用成功。

## 5. 历史排障记录

以下为 2026-10-24 的现象与处理结果。

| 问题 | 原因、处理与结果 |
| --- | --- |
| P01：`ENOTCACHED`、`only-if-cached` | 执行环境限制联网；允许联网后重试安装成功，伴随的清理 `EPERM` 未阻断重试。未改 registry、锁文件或版本；普通终端可查 `npm config get offline` |
| P02：npm 与依赖警告 | npm 11.6.2 不识别 `min-release-age=2`，另有 `autoevals@0.3.0` 的 pnpm 要求与依赖弃用警告。保留上游配置，CLI/RPC 通过；版本保护与评估功能未验证 |
| P03：模型 JSON 缺失 | 执行 `hydrate:model-data`、`check:model-data` 后通过；未触发缺失数据的启动异常，未改生成的 TypeScript 或锁文件 |
| P04：`ERR_MODULE_NOT_FOUND`，找不到 `dist/index.js` | `node packages/coding-agent/src/cli.ts --version` 绕过解析器；改用 `.ps1` / `.bat` 后返回 `1.0.0` |
| P05：自动选中 WSL Bash | 非默认盘符的 Git Bash 未被找到；默认 WSL 与隔离配置显式指定 Git Bash 的 RPC 命令均成功 |
| P06：子进程 `EPERM` / `E_ACCESSDENIED`、signal pipe 错误 | 自动化环境限制创建进程；允许本地子进程后重跑通过，不能直接归因于 Pi |
| P07：有模型目录仍无法对话 | 缺少凭据：`--list-models` 返回 `No models available`，`--print hello` 与 `auth check` 失败。需 `/login` 后再 `/model` |
| P08：交互测试缺少 tmux | Windows PATH、Git Bash、WSL 均未找到 tmux，未安装额外工具；自动化验证见上游 [交互测试说明](../../pi/.pi/skills/interactive-testing.md) |

补充处理：

- 模型数据 stale/missing：重新补齐并校验，不手写 JSON 或修改 `models.generated.ts`。
- 指定 Git Bash：将实际 `bin/bash.exe` 路径合并到 `settings.json` 的 `shellPath`，保留其他设置。
- 检查认证：`auth check --provider openai --json --no-refresh`；历史无凭据结果为 `not_ready / credentials_not_configured`，退出码 `1`。不要输出密钥；`--no-env` 不足以隔离认证，详见第 02 篇。
