# 04 消息历史与上下文准备

版本：Pi **v1.0.0**（`a13d35a74`） · 记录日期：2026-10-25

本模块展开 [第 03 篇](03-Agent基础与最小运行闭环.md) 最小闭环的第二步：用户输入后，Pi 如何加入消息历史、准备上下文与工具说明。

## 1. 子模块与阅读顺序

| 子模块 | 需要理解的问题 |
| --- | --- |
| [04.1 历史消息](04-1-历史消息.md) | 之前的交互保存成什么，当前输入如何接到历史后面？ |
| [04.2 上下文](04-2-上下文.md) | 哪些信息会进入本次请求，系统指令与消息如何组装？ |
| [04.3 工具说明](04-3-工具说明.md) | 模型如何知道有哪些工具、工具参数如何填写？ |

历史消息是上下文的来源之一；工具说明也是上下文的一部分。三者是概念上的分工，不代表请求中一定存在三个独立字段。

## 2. 从当前输入到模型请求

```text
已有会话 → 恢复当前分支的消息 → Agent 内存中的历史
                                  ↓
当前输入 → user 消息 → 与历史合并，加入系统指令和工具声明的变化
                                  ↓
                    上下文变换与消息转换
                                  ↓
                     规范化后交给模型运行时
```

以“读取 README 并概括用途”为例：

| 信息 | 本次请求中的作用 |
| --- | --- |
| 历史中的用户问题、模型回复、工具结果 | 提供此前的交互信息 |
| 当前 `user` 消息 | 提出这次任务 |
| 系统指令 | 提供行为规则、项目约定与工作目录等信息 |
| `read` 的工具声明 | 告诉模型如何申请读取文件 |

此时模型只获得读取能力的说明，尚未获得 README 正文；文件内容需在工具执行后作为结果回传。

| 阶段 | 源码入口 |
| --- | --- |
| 恢复历史 | [session-manager.ts](../../pi/packages/coding-agent/src/core/session-manager.ts) 的 `buildSessionContext()`，由 [sdk.ts](../../pi/packages/coding-agent/src/core/sdk.ts) 用于初始化 Agent |
